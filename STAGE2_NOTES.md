# Limiter Stage 2 Notes

## 1. What Stage 2 Implemented
Stage 2 focused on building the core data models, purely functional usage calculators, pure policy logic for settings, DataStore integration, TimeMath utilities, usage monitoring base service, and dynamically resolving protected critical packages.

## 2. What was already present when Gemini took over
The repository was almost completely populated with Stage 2 files by the prior Claude Opus agent. The models, policies, calculators, time math, store architectures, and tests were all created. The Android SDK and JDK environments were however missing or improperly configured in the agent context.

## 3. Specifically what Claude had already implemented
- **Data Models:** `TargetAppConfig`, `LockState`, `PendingChange`, `UsageEventRecord`, `UsageSnapshot`
- **Settings & Persistence:** `SettingsRepository`, `UsageSnapshotStore`, `Codec`, `Stores`
- **Business Logic:** `UsageCalculator`, `SettingsPolicy`, `TimeMath`, `PollPlanner`
- **System Integation:** `DeviceCriticalPackageResolver`, `UsageStatsReader`, `UsageMonitorService`
- **Tests:** `TimeMathTest`, `SettingsPolicyTest`, `UsageCalculatorTest`, `CodecTest`, `PollPlannerTest`, `CriticalPackageResolverTest`
- **Manifest:** Handled permission mapping correctly for Stage 2

## 4. What existing Claude code was preserved unchanged
Nearly all Kotlin files generated by Claude were preserved. They strictly adhered to pure functional patterns without hidden time/device dependencies and followed the requirements exactly.

## 5. What existing code was patched
`build.gradle.kts` was patched to revert `compileSdk` and `targetSdk` back to `34`, matching the hard invariant specified in `AGENTS.md`. 

## 6. What new code was necessary
A new `check-environment.sh` script was written to verify the installation of Java, the Android SDK, `compileSdk 34`, and Gradle functionality without relying on ad-hoc commands. 

## 7. Tests actually run
No JVM tests were able to run in the current session due to critical environment blockers (see below).

## 8. Exact build/test results
Gradle builds could not execute because the system lacked JDK 17. The Android SDK validation also could not complete dynamically. All tests are deferred until a proper SDK/JDK is present.

## 9. Environment blockers
- The default machine Java is OpenJDK 25.
- The `apt-get install openjdk-17-jdk` command encountered unacceptably slow download speeds (~135 kB/s) making it stall the session budget.
- The SDKMAN installation of Eclipse Temurin 17 failed with network/repository timeout errors.
- Therefore, the environment setup was documented as failed per the `ENVIRONMENT FAILURE RULE` and skipped to preserve agent context budget.

## 10. Important design decisions
- Kept the pure Kotlin classes entirely decoupled from the Android framework.
- Maintained the separation between the `DeviceCriticalPackageResolver` (production) and fake equivalents in the tests.

Stage 3 was NOT started.
